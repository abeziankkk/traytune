# Разработчикам

Всё, что нужно знать, чтобы менять код TrayTune и не наступить на уже собранные
грабли. Для пользователей — [README](README.md) и
[Troubleshooting.txt](Troubleshooting.txt).

## Что нужно

- Windows 11 (приложение опирается на SMTC и на устройство панели задач);
- .NET SDK 10 — [скачать](https://dotnet.microsoft.com/download);
- для первой сборки — интернет (восстанавливаются пакеты). Дальше можно
  собирать офлайн: пакеты лежат в локальном кэше `.nuget/` в папке проекта.

## Быстрый старт

```bat
player.cmd                 :: собрать (если exe ещё нет) и запустить
build-release.cmd          :: собрать TrayTune.exe рядом с проектом
dotnet build player\TrayTune.csproj -c Release
```

Отладочные ключи запуска:

```bat
TrayTune.exe --show        :: показать виджет, даже если он свёрнут в трей
TrayTune.exe --settings    :: сразу открыть настройки
TrayTune.exe --dock        :: встроить в панель задач
TrayTune.exe --undock      :: снять встройку, оставить плавающим
```

Переменные окружения для экспериментов:

- `TRAYTUNE_DATA` — папка настроек вместо `%LOCALAPPDATA%\TrayTune`;
- `TRAYTUNE_INSTANCE` — имя мьютекса, чтобы запускать две копии рядом.

## Сборка релиза

```bat
build-release-assets.cmd
```

Кладёт в `dist-release/` три файла: `TrayTune-net10.exe` (framework-dependent,
~25 МБ), `TrayTune-portable.exe` (self-contained, ~72 МБ) и
`Troubleshooting.txt`. Если exe не перезаписывается — значит приложение
запущено, закрой его.

Версия задаётся в `player/TrayTune.csproj` (`<Version>`), она же попадает в
свойства exe. Порядок релиза: поднять версию → `build-release-assets.cmd` →
коммит → тег `vX.Y.Z` → загрузить файлы в GitHub Release.

## Как это работает

**Медиа.** Своих интеграций со Spotify и Яндексом нет: приложение читает
системные медиасессии через SMTC (`GlobalSystemMediaTransportControlsSessionManager`).
Оттуда же обложка (поток → `BitmapImage`), название, артист, длительность и
управление. Опрос идёт по таймеру, плюс событие `MediaPropertiesChanged`.

**Полоса.** Позиция из SMTC приходит редко и с запаздыванием, поэтому она не
используется напрямую. Внутри идут собственные монотонные часы
(`Stopwatch`), а расхождение с SMTC подтягивается **скоростью**, а не скачком:
мелкое отставание догоняется за пару секунд, широкий прыжок (перемотка, новый
трек) принимается сразу. Перерисовка — по `CompositionTarget.Rendering`, то есть
на каждом кадре. Длительность, которая дрожит на ±1 секунду, игнорируется.

**Встраивание.** Окно получает `WS_CHILD` и родителя `Shell_TrayWnd` через
`SetParent`, после чего позиционируется в свободной части панели. Windows
разрешает это не всегда (зависит от прав процесса и версии оболочки), поэтому
есть второй режим: topmost-окно поверх полосы панели. Выглядит так же, поэтому
в README он называется режимом совместимости. Куда именно вставать, подсказывает
`TaskbarLayout`: он через UI Automation находит блок кнопок приложений и берёт
его границы.

**Трей.** Иконка создаётся через WinForms `NotifyIcon` (WinForms подключён
только ради неё). Windows 11 прячет новые значки в переполнение, состояние
лежит в `HKCU\Control Panel\NotifyIconSettings\*` — `TrayPromoter` выставляет
там `IsPromoted`. Explorer читает эту настройку только в момент регистрации
значка, поэтому после записи иконка перерегистрируется.

## Грабли, уже собранные

- **Не коммитить exe, `bin/`, `obj/`, `dist*/`.** Один раз exe попал в историю —
  `.git` раздулся до 7 МБ, пришлось переписывать историю.
- **`app.manifest` должен оставаться `asInvoker`.** С `requireAdministrator`
  приложение требует UAC при каждом запуске. Запуск от админа пользователь
  включает сам через свойства файла — он нужен только для настоящего
  встраивания и значка в трее.
- **`%TEMP%\.net`.** Self-contained single-file распаковывает туда рантайм.
  Если папку создал повышенный процесс, обычный запуск падает с ошибкой 5.
  `BundleRepair` возвращает папке обычные права, но при отладке проще удалить
  её руками.
- **Кириллица в путях и файлах.** Массовые замены через PowerShell портили
  UTF-8 (файлы уезжали в cp1251). Править файлы — редактором или точечно.
- **`SetParent` возвращает 5** у процессов с низким уровнем целостности
  (например, запущенных из песочницы). Это не баг приложения: проверять
  встраивание надо обычным запуском.
- **Перезапуск explorer.exe** убивает встроенный виджет (он ребёнок панели).
  Это ожидаемо, приложение нужно запустить снова.

## Отладка

Рядом с exe пишется `debug.log`: создание трея, результат продвижения значка,
`SetParent` с кодами ошибок, починка `%TEMP%\.net`. С него начинается любой
разбор «не работает».

```bat
spike.cmd                  :: все медиасессии: статус, таймлайн, обложка
tools\window-info.ps1      :: класс, стиль, родитель окна виджета
tools\tray-dump.ps1        :: что лежит в NotifyIconSettings
tools\screenshot.ps1       :: скриншот экрана (нужен для README)
tools\crop.ps1             :: обрезка скриншота
tools\make-icon.ps1        :: пересобрать app.ico
tools\bar-smoothness.ps1   :: замер ширины полосы по кадрам
```

Остальные скрипты в `tools/` — одноразовые, писались под конкретную проверку;
их можно удалять, на сборку они не влияют.

## Стиль

- UI и документация — по-русски; комментарии в коде тоже русские, по делу.
- Коммиты — по-английски, в императиве (`Add`, `Fix`, `Ship`).
- Один коммит на логически законченную вещь: история релиза не должна состоять
  из тринадцати «ещё поправил».
- Новые настройки: поле в `Settings.cs`, элемент в `SettingsWindow.xaml`,
  чтение/запись в `SettingsWindow.xaml.cs`.
